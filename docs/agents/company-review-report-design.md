# company-review HTML 리포트 DESIGN RULE

HTML 리포트를 만들 때만 읽는 문서다. 매번 싣지 않으려고 `.claude/agents/company-review.md` 본문에서 뺐다.
리포트는 **메인 대화가** 만든다. company-review 서브에이전트는 메인 대화를 볼 수 없어서, 대화에서 모은 정보를
빠짐없이 넣으라는 아래 규칙을 지킬 수 없다. 서브에이전트에 맡긴 검토 결과는 대화에서 모은 정보의 하나로 넣는다.

HTML 리포트는 **사용자가 "리포트 생성" 을 요청했을 때만** 만든다. 기업마다 궁금한 것이 달라서, 사용자는 대화로
필요한 정보를 다 모은 뒤 마지막에 생성을 요청한다. 그 전에는 조사 결과를 텍스트로 답하고 HTML 을 먼저 만들지
않는다. 생성할 때는 `.claude/agents/company-review.md` 데이터 절의 수집분에 **대화에서 모은 정보를 빠짐없이**
넣는다 — 다 넣은 뒤 대화에 나온 수치·공시·기사를 하나씩 대조해 빠진 것이 없는지 확인하고, 없는 데이터는 "데이터 없음" 으로 남긴다
(1쪽은 아래 "요약 1쪽" 의 단서 규칙을 따른다).

파일은 저장소 루트 `research/reports/<영문 회사명>-<종목코드>-report-<YYYY-MM-DD>.html` 에 둔다(gitignore, worktree 에서도
메인 체크아웃의 `research/`). 1쪽 판단 필드는 `review record` 로 남긴 판단과 같은 값이다 — 심화에서 판단이 바뀌었으면
리포트 전에 새로 기록한다.

생성 요청에 요약 형식이 없으면 만들기 전에 묻는다. **A 증권사형**은 기업을 아는 독자에게 판단·가격·실적을 한 장에,
**D 초보형**은 처음 보는 독자에게 답 한 줄과 쉬운 말 체크를 준다. 고른 형식은 1쪽에만 쓰고 2쪽부터는 어느 쪽이든 같다.

목적은 정보를 다 넣으면서도 **넓게 본 뒤 자세히 보는 순서**가 지켜지는 것이다.

## 구조: 요약 1쪽 → 큰 그림 → 질문 지도 → 질문별 장

`company-review.md` `## 리포트` 의 텍스트 순서는 HTML 에 쓰지 않는다. 판단 절의 필드(판단·확신도·`horizon_days`·
기준가·진입 구간·목표가·손절가·무효화 조건·`data_as_of`)는 Q7 에 빠짐없이 넣고, 1쪽에는 "요약 1쪽" 이 정한 것만 둔다.

1. **요약 1쪽** — A 또는 D 중 고른 하나. 아래 "요약 1쪽" 절.
2. **큰 그림 1쪽** — 사업 모델 흐름도(고객 → 회사 → 최종 판매) 아래에 작은 차트 6개(3×2). 연간 매출, 분기
   이익률, 지역(또는 부문) 성장, FCF, 순차입금, 주가처럼 질문 장마다 하나씩 뽑는다. 카드마다 한 줄 결론과
   `자세히 → Qn` 링크.
3. **질문 지도 1쪽** — 질문 카드 그리드. 카드마다 한 줄 답, 신호(좋음·보통·주의·개요 색), 쪽 번호, 장으로 가는 링크.
   신호는 `company-review.md` 분석 8단계 다섯 가지 체크의 판정을 그대로 쓴다(Q3 성장·수익성 두 개, Q4 현금, Q5 빚,
   Q6 가격). A 를 골라도 판정해 싣는다. 나머지 질문은 개요 색. 질문별 장의 녹색 띠 신호도 같은 판정이다.
4. **질문별 장** — 질문 하나에 한 쪽 이상. 순서는 녹색 띠(번호·질문·한 줄 답·신호) → 핵심 수치 3개 → `한눈에`
   (차트 1~3개) → `자세히`(회색 바탕, 표·원문 요약·주석). 같은 주제의 차트와 표는 한 장에 모은다.
5. **부록** — 데이터 출처 표, 참고 기사 링크, 한계, 마지막 줄 "투자 조언이 아닌 의사결정 보조 리포트".

기본 질문은 아래 일곱이다. 대화에서 따로 파고든 주제(예: 설비투자 사용처, 자회사 CB)는 가장 가까운 질문의
`자세히` 에 넣고, 한 장을 채울 만큼 크면 질문을 하나 더 만든다.

| 질문 | 한눈에 | 자세히 |
| --- | --- | --- |
| Q1 무엇을 하는 회사인가? | 제품 구성, 연혁 | 회사 개요(사업 방식·고객·대표 제품·경쟁력), 법인별 제품·단가, 내수·수출, 원재료 |
| Q2 어디서 돈을 버나? | 지역·부문 매출, 법인별 이익 | 법인별 실적 표, 생산능력, 거점·증설 계획 |
| Q3 잘 팔리고 남기나? | 분기 매출, 영업이익 vs 순이익, 연간 추이 | 분기 표(영업외·실효세율 포함), 손익계산서, DART 수익성·성장성 지표, `quality` 의 ROIC·DuPont 분해 |
| Q4 번 돈이 현금으로 남나? | 영업CF vs CAPEX, 건설중인자산, 투자처 | 설비투자 비율, 현금흐름표, 자산 변동, 파생 지표, 오너 어닝스·발생액·주주수익률(`assumed_zero` 항목 표기) |
| Q5 빚은 감당할 만한가? | 순차입금, 앞으로 나갈 돈 | 재무상태표, DART 안정성 지표, 차입 구조, 약정·우발부채, 사채·CB, F-Score·Altman Z''·Z |
| Q6 주가는 싼가? | 밸류에이션, 5년 PER·PBR 밴드(현재 분위 점), 증권사 의견, 월봉 주가(가격선·목표가 점선)와 1M/3M/6M/12M 수익률 | FCF 수익률·EV/EBIT·이익수익률·PEG, 시장이 반영한 ROE·성장률(`implied-expectations`) vs 실측, 52주 고저·외국인 지분율, 기술적 지표·RS(1M)·업종 RS, 매크로 민감도(t값 큰 계수만), 공시·뉴스 일지 |
| Q6-2 경쟁사 대비 어디쯤인가? | 매출 성장률·영업이익률·순현금* 가로막대, 같은 시작월=100 으로 지수화한 주가 선 | `company-review.md` 분석 5단계의 비교표(종목이 열), 회사별 요약 |
| Q7 그래서 어떻게 하나? | 판단과 조건, 다음 실적에서 볼 것 | bull/bear, 시나리오(기저율 사분위에서 출발한 확률과 조정마다 근거 수치·%p), `peer_rank` |

Q6-2 는 대화에서 비교 기업을 다뤘을 때만 넣는다. 질문 지도에 카드 하나를 더하고, 큰 그림 차트 6개 중
하나를 비교 차트(현금 제외 PER* 처럼 차이가 가장 큰 지표)로 바꾼다. 지수화 주가 선은 본 종목만 녹색이고
비교 기업은 회색 톤이다. 비교표 제목에 가격 기준일과 재무 회계기준일·연결 여부를 적는다.

Q6 밴드 차트는 5년 PER(또는 PBR) 배수 선 위에 `quantiles` 의 p25·median·p75 가로선(min·max 는 축 끝 값)을 긋고 현재 값을 녹색 점으로 찍는다. 밴드는 직전
사업연도 EPS·BPS 기준이라 캡션이나 `자료:` 줄에 "TTM PER 아님" 과 EPS 연도(`current.eps_bps_year`)를 적고, 같은 쪽의
TTM PER 과 한 숫자로 섞지 않는다. 로컬 캐시 값(밴드·RS·β·기저율)은 `자료:` 줄에 캐시 마지막 적재일을 적는다.

## 요약 1쪽

1쪽은 결론과 그 결론을 바꿀 조건만 담는다. 근거는 2쪽부터이고 A·D 가 같다 — 형식은 보여 주는 방식만 바꾼다.

- **주장마다 근거 장**: 핵심 포인트(A)·체크 판정(D)·조건 끝에 `→ Qn` 링크를 단다. 1쪽 수치는 그 장의 수치와
  같은 값·같은 반올림이다. 1쪽에만 있고 장에 없는 수치는 두지 않는다.
- **판단 필드**: 판단·기간(D 는 다음 판단 날짜)·확신도·기준가·재검토가·이탈가·다음 확인 이벤트. buy·sell 이면
  목표가·손절가도. 진입 구간과 나머지 무효화 조건, `data_as_of` 전체는 Q7 에 둔다.
- **넣지 않는 것**: CLI 명령어, 접수번호·corp 코드·보고서 코드·계정 코드(M220000 같은), YAML, 판 비교("10-26판
  대비"), 백테스트·셋업 그룹 점수, MACD·볼린저·스토캐스틱·ADX, 계산 공식(ATR 식 같은). 이것들은 장·부록에 둔다.
- **숫자**: 비율·배수는 소수 1자리(15.0배, 4.3배, 17.4%). 금액은 억원 정수, 조원이면 소수 2자리. 기준가·재검토가·
  이탈가·목표가·손절가는 주문에 쓰는 값이라 원 단위로, 목표가 평균 같은 대푯값은 만원 소수 1자리(36.5만원)로.
- **단서는 하단 한 줄**: `*계산값` · `E 는 한국투자증권 한 곳의 추정, 컨센서스 아님` · `— 데이터 없음` · 자료와
  기준일. 본문에는 `*` 와 `—` 만 남긴다. 공시/보도 색 구분은 2쪽부터 쓴다.
- **대칭 금지**: 핵심 포인트·체크를 좋은 점과 나쁜 점의 개수로 맞추지 않는다. 판단을 크게 움직인 것부터 쓴다.

### A 증권사형

위에서 아래로. 괄호는 본문 높이 1,043px 중 대략의 몫이다.

1. 상단 띠(24px) — COMPANY REPORT · 업종 · 시장 · 가격 기준일 · 재무 회계기준일·연결.
2. 종목명·코드·한 줄 정체성, 의견형 헤드라인 2줄 이내(100px).
3. 2열(320px). 왼쪽 236px: 판단 박스(녹색 바탕, 판단·한글 뜻·기간·확신도)와 판단 가격 사다리(재검토가·기준가·
   이탈가, buy·sell 이면 목표가·손절가. 가격마다 무슨 선인지 한 줄). 오른쪽: 번호 붙은 핵심 포인트 3개(굵은 한 줄
   + 근거 1~2문장 + `→ Qn`).
4. KPI 띠 5칸(72px) — 시총, PER(최근 1년), PBR, 목표가 평균·현재가 대비, 증권사 의견 분포(최근 90일).
   비교 기업이 있으면 PER 칸 아래에 비교 기업 중앙값을 한 줄.
5. 판단을 바꿀 조건 2칸(80px) — ▲ 한 단계 올리는 조건(watch 면 "매수 검토로"), ▼ 한 단계 내리는 조건("관심을 접는").
6. 실적 표 4행(200px) — 최근 2개 연도, 최근 1년*, 추정 E 1개 연도 × 매출·영업이익·영업이익률·지배순이익·PER·ROE.
   캡션은 결론 문장, E 행은 추정색.
7. 꼬리말(56px) — 다음 확인 이벤트와 날짜, 단서 한 줄, 면책.

### D 초보형

1. 머리줄 — 종목명 · 코드 · 업종 · 기준일 종가.
2. "지금 살까?" 와 답 한 줄(44px 안팎 굵게). 답은 판단을 쉬운 말로 옮긴다: buy "살 만하다", hold "가진 사람은
   들고 간다", sell "줄이거나 판다", watch "아직은 기다린다". 그 아래 판단 · 다음 판단 날짜 · 확신도.
3. 2분 설명 — 3문장 이내: 무엇을 하는 회사인지 / 좋은 점 / 걸리는 점. 용어 없이.
4. 다섯 가지 체크 표 — 성장·수익성·현금·빚·가격 × 신호 × 쉬운 말 근거 1줄 + `→ Qn`. 판정은 `company-review.md`
   분석 8단계 기준 그대로다. 신호는 색과 모양(● 좋음 ◐ 보통 ○ 주의)을 함께 써 색만으로 가르지 않는다.
   표 제목은 결론 문장("성장은 좋고, 현금이 걸린다").
5. 이렇게 하세요 3줄 — 날짜·가격 기준: 다음 실적일에 볼 것, 재검토가, 이탈가. buy·sell 이면 목표가·손절가 줄.
6. 꼬리말 — 용어 풀이(1쪽에 나온 용어만), 단서·출처 한 줄, 면책.

이동평균은 "최근 N거래일 평균 주가" 로 쓴다. 가격선 이름도 같다(재검토가 = 최근 50거래일 평균 주가).

## 지면과 차트

- 색은 만원권 팔레트다. 강조색은 녹색 `#1f5c4a` 한 가지(아래 "녹색" 은 모두 이 색). 글자 `#1d2a24`, 보조 글자
  `#5d6b62`, 선 `#cad8cc`, 바탕 `#e2ebe2`, 옅은 칸 `#eef4ee`, 차트의 나머지 막대 `#b5c7ba`, 추정 `#9a6b00`.
  "좋음" 신호는 강조색과 헷갈리지 않게 연두 `#5a9a2e`, "나쁨" 은 빨강 `#c0392b`. 강조색 외의 파랑·녹색은 쓰지 않는다.
- **쪽은 A4 고정**: 연두 바탕 위 흰 `.page` 794×1123px(210×297mm), 상단 녹색 3px 줄, 안쪽 여백 위아래 40px·
  좌우 48px. 쪽 높이는 내용에 맞춰 늘리지 않는다. 인쇄용이라 라이트 고정이다.
- **쪽마다 높이 예산**: 머리 띠와 꼬리말을 먼저 두고 남은 높이를 블록에 나눈다. 꼬리말은 쪽 바닥에 붙인다
  (`margin-top: auto`). 블록 간격은 쪽 안에서 한 값(16~28px)으로 맞춘다.
- **넘치면 쪽을 나눈다**: 글자를 줄여 밀어 넣지 않는다(본문 14px, 표 13px, 주석 12px 아래로 내리지 않는다).
  장이 넘치면 다음 쪽 머리에 "Qn (계속)" 을 달고, 쪽을 넘는 표는 머리행을 다시 단다.
- **비면 채운다**: 남는 높이가 쪽의 15% 를 넘으면 간격을 벌리지 말고 차트를 키우거나 같은 장의 `자세히` 를 당긴다.
- 화면에서는 쪽 사이 24px 로 세로로 쌓는다. 화면이 794px 보다 좁으면 1열로 접지 않고 쪽 전체를 화면 폭에 맞게
  줄인다(`zoom`). 인쇄는 `@page { size: A4; margin: 0 }`, 쪽마다 `break-after: page`, `print-color-adjust: exact`.
  PDF 배포는 같은 HTML 을 인쇄해 1~2쪽만 뽑는다.
- 그림·표에 문서 순서대로 `그림 N`·`표 N` 번호를 붙이고, 캡션은 **결론 문장**("분기 매출: 2026Q2 사상 최대")이다.
  캡션 위 녹색 2px 줄, 바로 아래 `자료: 출처, 단위, 기준일` 한 줄.
- 한 차트에 메시지 하나: 말하려는 막대·점만 녹색, 나머지는 회색. 빨강·연두는 적자·기준선 초과 같은 좋음/나쁨에만.
  고점·저점·이벤트·기준선 값은 차트 안에 직접 쓴다.
- 무효화 조건의 가격(이동평균)과 목표가는 주가 차트에 점선으로 그린다.
- 근거 등급을 구분한다(2쪽부터): 공시는 녹색, 언론 보도 수치는 회색으로 칠하고 범례에 적는다. 추정(KIS)은 표에서
  색을 달리하고 "컨센서스 아님" 을 쓴다. 계산값에는 `*` 나 "계산값" 표시.
- 한 HTML 파일, 차트는 외부 라이브러리 없이 인라인 SVG. 숫자 열은 `tabular-nums`·우측 정렬.
- 글자끼리 겹치지 않게 여백을 계산한다. 음수 세로 막대는 값 라벨 높이만큼 x축 라벨 위를 비우고, 음수 가로
  막대는 값 라벨 폭만큼 범주 라벨 오른쪽을 비운다. 선 차트 끝 라벨이 겹치면 위아래로 밀고, 첫 x 라벨은 왼쪽 정렬.
- 다 만든 뒤 렌더링해 겹침과 쪽 넘침(`.page` 의 `scrollHeight > clientHeight`)을 본다. headless Chrome 이 없으면
  macOS `qlmanage -t -s 1400 -o <폴더> <html>` 로 첫 화면 PNG 를 얻는다(쪽마다 보려면 쪽을 떼어 낸 HTML 로).
